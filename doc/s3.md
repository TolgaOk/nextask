# S3 storage

Works with S3-compatible services, including Hetzner. Nextask includes the storage client.
[Configure the address, bucket and keys](configuration.md) before use. The bucket must already exist.
Workers need permission to read file details and upload files. Downloads need permission to list and read files.

## Upload

```sh
nextask enqueue --with git --with s3 \
  --set 's3.include=["outputs/**"]' \
  --set 's3.exclude=["**/*.tmp"]' \
  --set 's3.final_include=["reports/**"]' './job.sh'
```

The worker uploads matching files every 60 seconds by default, then again when the command finishes.
Files go to `<remote>/<TASK_ID>/<file-path>`, for example `s3://my-bucket/my-project/export-42/outputs/result.json`.
Changed files replace the stored copy; unchanged files are skipped. Nothing is deleted automatically.

## Choose files

- Uploads require `include` or `final_include`. Paths are relative to `root`.
- `include` selects files for regular and final uploads. `final_include` adds files only at the end.
- `exclude` always wins, regardless of option order. `.git` and `.nextask` are always skipped.
- `*.json` matches files in the top directory; `**/*.json` includes subdirectories. `outputs/**` selects everything below `outputs`.
- No matching files is allowed for uploads. A download with no matches returns an error.

## Download

```sh
nextask s3 fetch TASK_ID --to ./inputs
nextask s3 fetch TASK_ID --to ./inputs --include 'outputs/**' --exclude '**/*.tmp'
nextask s3 fetch TASK_ID --to ./inputs --dry-run
nextask s3 fetch TASK_ID --to ./inputs --overwrite
```

Use the same storage address, bucket and path as the upload. No DB connection or task record is needed.
Downloads select all stored files by default; upload filters do not apply.
`--to` is required. Existing files need `--overwrite`. `--dry-run` checks and lists files without downloading.
Repeat `--include` or `--exclude` to add patterns; exclusions win.
`--timeout` defaults to `5m` for listing and each file, with a maximum of `24h`.

Nextask checks file sizes and saved checksums when available, and rejects unsafe paths or conflicting names.
If a download fails, completed files remain. Downloading a running task gets whatever is stored at that time.

Another task can run the same command:

```sh
nextask enqueue 'nextask s3 fetch TASK_ID --to inputs && ./process.sh inputs'
```

That worker needs Nextask on its command path and its own storage settings and keys.
The submitting machine's local config is not copied into this command.

See [all S3 settings and defaults](configuration.md#s3-settings).

## Failures and cleanup

- Failed regular uploads are reported and retried at the next check.
- Finishing or cancelling a task waits for the final upload, up to `final_timeout`. A failed command keeps its original exit code.
- Abrupt instance loss keeps only files already uploaded. Killing a process may prevent the final upload.
- Uploads temporarily copy files on worker disk. Leave room for the files being uploaded at once. Files changed while being read are retried later.
- `nextask remove` keeps stored files. Delete them through your storage provider, or set its automatic deletion rules.
