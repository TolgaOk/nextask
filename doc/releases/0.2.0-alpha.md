# 0.2.0-alpha

First alpha of the 0.2 task and integration design.

- Opt-in Git snapshots and S3-compatible artifact uploads, composed with ordinary commands.
- Fetch stored artifacts with `nextask s3 fetch TASK_ID --to DIR`, with include/exclude filters, dry runs, and explicit overwrites. Fetching requires no database connection.
- Caller-supplied task IDs, worker task environment, and shared configuration with environment-only secrets.
- Consistent list flags, duration units, output, and tag filtering; corrected `wait --any` and stale-worker filtering.
- Confirmed daemon startup, cancellation recovery, and durable replay of finished task results after worker loss.

Before upgrading, replace literal credentials with environment references or supply
complete connection URLs through the environment. S3 endpoint URLs carry access-key
and secret-key references. Run `nextask init db` and upgrade workers before enqueueing
integrated tasks. Config files are validated before overrides, so replace literal
credentials in both global and project configs. Worker-failure classification and
automatic task requeue remain planned.

See [upgrade instructions](https://github.com/TolgaOk/nextask/blob/v0.2.0-alpha/doc/upgrading.md), [integrations](https://github.com/TolgaOk/nextask/blob/v0.2.0-alpha/doc/integrations.md),
and [configuration](https://github.com/TolgaOk/nextask/blob/v0.2.0-alpha/doc/configuration.md) for migration details and recovery limits.
